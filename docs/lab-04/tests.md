## Execution notes

- Use a disposable PostgreSQL database for migration/recovery and performance testing. Do not apply a rollback that could delete newly recorded actions.
- DB-01 and PERF-01 run only when `LAB4_TEST_DATABASE_URL` points to loopback PostgreSQL. Each creates and drops a uniquely named temporary schema; neither modifies `public` or any remote database.
- API tests cover role/ownership boundaries independently of UI hiding.
- Dashboard tests assert exact query scope, server-returned metric windows, null legacy timestamp exclusion, drill-down parity and pagination, stable ordering, and explicit zero buckets.
- Playwright captures cover the implemented screens at 1440, 768, and 375 px. The screenshot index maps each capture to its case and viewport; [`visual-review.md`](visual-review.md) records the final-main review and its limits.
- Earlier candidate runs on PR #80 (`c6aef91`) and PR #81 (`fb0e13f`) are retained as development evidence. The complete server/client suites, builds, and Playwright suite were rerun against final main `5dd4ff0`; the exact commit/tree and totals are stated above and in the separate report.
- PERF-01 response times are a local smoke measurement, not a production SLA. See the run note for data volume and index plans.
- The separate PDF is not committed to the repository. Its screenshots identify their capture context, and its claims distinguish the verified final application source from earlier candidate runs.
